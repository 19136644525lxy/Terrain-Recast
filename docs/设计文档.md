# Terrain Recast 地形重铸模组 · 设计文档

> 目标平台：Minecraft 26.3 · Fabric Loader 0.20.1 · Fabric API 0.165.0+26.3 · Java 25
> 包名：`yifei.terrain.recast` · MOD_ID：`terrain_recast`
> 本文档基于对三个参考地形模组源码的深度分析，规划一个融合各家优点的全新地形重铸模组。

---

## 一、调研背景

三个参考模组代表了两种截然不同的地形改造哲学：

| 模组 | 加载器 | 目标版本 | 哲学 |
|---|---|---|---|
| ReTerraForged（RTF） | Architectury（Fabric+NeoForge） | 26.2 | 拟真地形：Cell 单元格 + 原生密度函数接入 |
| UltraTerraForged（UTF） | Architectury | 26.3 | RTF 的 26.3 移植增强版，补全预设 GUI/分享码/兼容层 |
| BigGlobe | Fabric | 1.19.2–1.20.4 | 程序化生成：自研脚本引擎 + 柱体世界模型 + 捆绑玩法内容 |

三者均有可取之处，也各有致命短板。新模组的目标是：**取 RTF/UTF 的"原生密度函数 + Cell 地形引擎"骨架，取 BigGlobe 的"柱体抽象 + 噪声库 + 程序化树木"思想，剔除脚本引擎与玩法捆绑，以数据驱动、最小 Mixin、生命周期安全的并发模型重构**。

## 二、参考模组深度分析

### 2.1 ReTerraForged（NeoTerraForged-26.2）

#### 架构
- Architectury 三模块：common 承载全部逻辑，fabric/neoforge 仅做入口与平台实现。
- 平台抽象走 `@ExpectPlatform`：`ConfigUtil` / `ModLoaderUtil` / `RegistryUtil` / `DataGenUtil`，common 端统一调用。
- 入口 `RTFCommon.bootstrap()` 集中注册 worldgen、density function、noise、feature、surface rule、structure 与 data registry。

#### 核心机制
- **Cell 单元格引擎**（`world.worldgen.cell.Cell`）：地形以"单元格"为最小区域单位，单格携带高度、侵蚀、气候、群系、地形类型等字段。Cell 对象通过 `ThreadLocalPool` + `Resource` 池化复用，避免 GC 压力。
- **密度函数桥接**（`densityfunction.CellSampler`）：把 Cell 字段（height/continent/erosion/temperature/moisture，以 `Marker`/`Field` 枚举定义）暴露为**可序列化的真实 DensityFunction**，内部以 `ThreadLocal<Cache2d>` 缓存当前区块采样，减少重复 world lookup。
- **生成上下文**（`GeneratorContext`）：串联 Preset、Noise、TileGenerator、WorldFilters、TileCache、WorldLookup。
- **过滤管线**（`WorldFilters`）：按预设依次施加 steepness（陡峭度修正）、beach（海滩压平）、erosion（侵蚀）、smoothing（平滑）、noise correction。
- **并发缓存**（`concurrent.cache.Cache`）：单线程定时清理 `ExpiringEntry`，服务于 `TileCache`、`RiverCache` 等。

#### 优点
1. 地形接入原版密度函数体系 → 数据包/预设可调整地形，扩展性极强。
2. Cell 抽象让地形有"区域"概念（大陆、侵蚀带），这是拟真地形的基础。
3. 对象池 + 区块级缓存，采样性能优秀。

#### 缺陷
1. **已停止维护**，停留在 26.2。
2. 缓存清理线程与世界生命周期解耦，世界卸载后若未释放 → 内存泄漏隐患。
3. TerraBlender 兼容靠 Mixin 硬 hack（`mixin.terrablender.*`）。
4. 预设系统纯代码写死，无 GUI、无分享机制。
5. 线程池（`ThreadPools`）全局静态，服务器重启场景下存在任务残留风险。

---

### 2.2 UltraTerraForged（ultraterraforged-26.3）

RTF 的 26.3 移植 + 增强版，是三者中最接近目标版本的参考。

#### 相对 RTF 的增量
- **预设选项体系**（`preset.option.*`）：`Option`/`Category`/`Page`/`PresetOptions`，选项类型含 Bool/Int/Float/Enum，支持分页 GUI 可视化编辑。
- **预设分享码**（`PresetShareCode`）：预设压缩为 `UTF1:` 前缀 Base64 字符串，带长度与损坏校验。
- **预设库**（`PresetLibrary`）与命令系统（`LocateTerrainCommand`/`UTFCommands`）。
- **兼容层**（`compat.*`）：TerraBlender、WorldPreview、C2ME（OpenCL）、Streams 河流、Alex's Caves；`mixin.plugin.MixinPlugin` 按模组存在性条件加载对应 Mixin。
- **自定义含水层**（`VolumeAquifer`）：按区块最高地面限制查询范围，`RaisedWaterGuard` 保护河流/湖泊水面不被 carving 破坏。
- **性能开关**（`WorldGenFlags`）：ThreadLocal 控制 fast cell lookups。
- **26.3 地形注入重写**：CellSampler/NoiseSampler 改为真实 density function，经 `RandomState`/`CompileContext`/`ContextBoundSampler` 接入，取代旧版 visitor 与 NoiseChunk 内部 hack。
- **完整测试套件**：30+ 测试类（CellCacheTest、LandformTest、RiverFlowTest、PresetShareCodeTest 等），附 `TestBootstrap`/`PresetDatapack` 测试基建。

#### 缺陷（重要警示）
1. **移植创伤**：其 `docs/porting/26.3.md` 自述移植过程出现 **873 个编译错误、access widener 失效、11 个 common mixin 目标丢失**——说明对 MC 内部结构依赖极深，每次版本升级都是灾难。
2. Mixin 数量庞大（20+ 个），每个注入点都是与其他模组的潜在冲突点。
3. 兼容层全部是条件 Mixin，hack 程度高，兼容模组更新即可能崩溃。
4. `WorldGenFlags` 用 ThreadLocal 做全局开关，若线程复用（线程池）时标志残留，会产生串扰。

### 2.3 BigGlobe

#### 架构
- Fabric 单加载器；`BigGlobeMod`（通用）/`BigGlobeClient`/`BigGlobeServer` 三入口分工。
- `versions` 包用 `#if MC_VERSION` 预处理做 1.19.2–1.20.4 跨版本兼容（如 `BlockPosVersions`、`RegistryVersions`）。

#### 核心机制
- **自研脚本引擎**（`builderb0y.scripting`）：ExpressionParser → 字节码编译，通过 `ScriptedFeature`/`ScriptedGrid` 接入地形生成；`ColumnScriptEnvironmentBuilder` 把 ColumnValue 注册为脚本变量/函数。
- **ColumnValue 注册表**（`columns.ColumnValue`）：统一向世界暴露数据访问口，预注册覆盖主世界/下界/末地的 biome、高度、温度、湿度、侵蚀、洞穴、岩层、云等数十种列值，支持 `namespace:name` 查找。
- **柱体世界模型**（`columns.*`）：`WorldColumn` 抽象一列方块的全部数据；`ChunkOfColumns` 一次并行填充 256 列；非 BigGlobe 世界回退 `VanillaWorldColumn`——生成逻辑只面向"列"，不直接操作方块。
- **Grid 噪声库**（`noise.*`）：Grid1D/2D/3D 接口 × Value/Worley/Cubic/Smooth/Layered/SineWave/Stalactite 等数十种实现，远严于原版噪声。
- **程序化树木**（`trees.*`）：`TreeGenerator` + `TrunkFactory` + `BranchConfig` + `LeafDecorator`，参数化生成任意形态树。
- **自定义 ChunkGenerator**（`BigGlobeChunkGenerator`）：持有 SortedFeatures/SortedStructures/profiler/recycler。
- **捆绑玩法内容**：弹弓、探洞绳、岩块实体、灵魂岩浆、彩色告示牌等。

#### 优点
1. **柱体模型是极佳抽象**：把 3D 世界生成降为 2.5D（列数据 + Y 轴规则），逻辑清晰且利于并行。
2. ColumnValue 注册表 = 数据驱动世界的范本，附属模组可直接消费。
3. 噪声库极其丰富，程序化树木远超原版。
4. 异步命令（`AsyncLocateCommand`）不卡主线程。

#### 缺陷
1. **脚本引擎是灾难级维护负担**：自研词法/语法/字节码编译，几千行代码，安全边界模糊（脚本即任意字节码），调试体验差。
2. 多版本预处理器让代码可读性极差。
3. 地形 + 玩法内容捆绑，违背单一职责，用户无法只要地形。
4. Fabric-only。
5. 结构生成（Labyrinth 迷宫）在边界区块有可靠性问题。

## 四、Terrain Recast 总体设计

### 4.1 定位

**纯地形重塑模组**：重铸主世界地形（大陆、山脉、河流、海岸、洞穴、地层），气候驱动群系分布，程序化树木与地物点缀。**不做脚本引擎，不捆绑玩法内容，不加新方块/物品/实体**（树木等用原版方块）。

### 4.2 设计原则

1. **数据驱动优先**：凡能用 Codec/JSON/数据包表达的，绝不硬编码；预设 = 数据包资源。
2. **官方扩展点优先**：密度函数、表面规则、特征、群系源全部走注册表；Mixin 仅用于无扩展点的环节。
3. **生命周期安全**：一切缓存/线程池绑定 `MinecraftServer` 生命周期，世界卸载即释放，杜绝泄漏。
4. **单文件 ≤ 500 行**，按功能分包，多预留接口降低附属模组开发难度。
5. **线程安全**：ConcurrentHashMap / CopyOnWriteArrayList / AtomicLong，禁止裸 HashMap 跨线程。
6. **性能预算**：单区块地形采样不劣于原版 1.5×；缓存命中率 ≥ 90%。

### 4.3 功能清单

#### A. 地形引擎（核心）
- A1. Cell 单元格系统：大陆尺度 Cell（含高度/侵蚀/地形类型/气候字段），对象池复用
- A2. 大陆生成：板块式大陆 + 深海 + 岛屿链
- A3. 山脉系统：褶皱山、断块山、火山锥三种山形
- A4. 侵蚀模拟：水力侵蚀（下切河谷）+ 热侵蚀（坡度均衡）迭代
- A5. 过滤管线：陡峭度修正 → 海滩压平 → 侵蚀 → 平滑 → 噪声修正（可配置顺序与开关）
- A6. 地层系统（Strata）：按深度分层的岩层（表土/沉积岩/变质岩/深板岩），Y 轴 + 噪声扰动
- A7. 海岸与海滩：动态海平面、沙滩/砾石滩/峭壁海岸三类岸线

#### B. 密度函数接入（26.3 原生）
- B1. 注册真实 `DensityFunction` 类型：cell 高度、大陆性、侵蚀、温度、湿度采样器
- B2. 经 `RandomState`/`CompileContext` 接入 NoiseRouter，替代 NoiseChunk 内部 hack
- B3. 全部地形参数暴露于数据包 `worldgen/noise_settings`，数据包可覆写

#### C. 气候与群系
- C1. 气候采样器：温度/湿度/大陆性/侵蚀/怪异度五维参数
- C2. 气候驱动群系重排：群系按气候带自然过渡（热带→温带→寒带纬度带 + 海拔修正）
- C3. 群系边界混合：过渡带宽度可配
- C4. 可选 TerraBlender 兼容（条件 Mixin，独立开关）

#### D. 水文系统
- D1. 河流生成：源于山地、沿坡度下切、汇入海洋/湖泊，河宽随流量递增
- D2. 湖泊：洼地积水，水位保护（借鉴 `RaisedWaterGuard`，防止 carving 切穿水面）
- D3. 自定义含水层：按区块地表高度限制查询范围（借鉴 `VolumeAquifer` 思想）
- D4. 地下水位分层：浅层潜水 + 深层承压水

#### E. 洞穴与地下
- E1. 洞穴雕刻接入地层（不同岩层洞穴壁材质不同）
- E2. 巨型洞穴（罕见，伴随地层断裂）
- E3. 含水层与洞穴交互保护

#### F. 植被与地物
- F1. 程序化树木引擎：树干（TrunkFactory 参数化曲线）+ 树枝（分叉角/长度/高度）+ 叶冠（形状模板）
- F2. 内置树种：黄山松、苏格兰松、石松等（参考 RTF/UTF 的 NBT 模板 → 转为程序化参数）
- F3. 地物：侵蚀柱、磁盘（黏土/沙砾）、沼泽地表、装饰雪、灌木
- F4. 全部地物走原版 Feature 注册表，数据包可增删

#### G. 预设系统
- G1. 预设 = 数据驱动资源（JSON + Codec 序列化）
- G2. 预设选项体系：分页（Page）→ 分类（Category）→ 选项（Bool/Int/Float/Enum），GUI 可视化编辑
- G3. 内置预设：默认 / 壮丽山河（大山大河）/ 群岛 / 高原 / 平缓丘陵
- G4. 预设分享码：`TRC1:` 前缀 + 压缩 Base64 + 校验和
- G5. 预设库：本地保存/重命名/删除/导入导出

#### H. 世界创建 GUI
- H1. 创建世界界面注入"地形重铸"预设选择页（条件 Mixin `CreateWorldScreen`）
- H2. 灰白半透明现代 UI 风格（遵循用户偏好），无阴影文本
- H3. 选项实时预览说明文本

#### I. 命令
- I1. `/terrainrecast locate terrain <类型>`：异步定位最近地形类型（不卡主线程）
- I2. `/terrainrecast preset export/import`：分享码导入导出
- I3. `/terrainrecast info`：脚下 Cell 的气候/侵蚀/地形类型调试信息

#### J. 配置系统
- J1. Cloth Config API + ModMenu 集成
- J2. 性能配置：缓存大小、线程数、fast cell lookup 开关
- J3. 兼容开关：TerraBlender / WorldPreview / C2ME 逐条开关
- J4. 语言文件 zh_cn + en_us 同步维护

#### K. 兼容与集成
- K1. TerraBlender（可选，条件 Mixin）
- K2. WorldPreview（暴露采样接口）
- K3. C2ME（声明线程安全，不做 OpenCL hack）
- K4. DistantHorizons（保证密度函数可重入，供 LOD 采样）
- K5. 数据包/附属模组 API：`TerrainRecastApi` 暴露 Cell 查询、ColumnValue、预设注册

#### L. 测试与数据生成
- L1. 测试基建：TestBootstrap + 预设快照测试（指纹比对）
- L2. 关键测试：Cell 缓存命中、侵蚀收敛、河流连通、分享码往返、Mixin 目标校验
- L3. Fabric datagen：noise_settings、world_preset、tags、lang 全量生成

### 4.5 关键子系统设计

**4.5.1 Cell 引擎**：Cell 对象池用 `ThreadLocal` + 引用计数；区块级 2D 缓存挂到 `RandomState` 生命周期（随世界卸载销毁）；字段序列化走 Codec，供密度函数 Marker 暴露。

**4.5.2 密度函数接入**：全部采用 UTF 的 26.3 方案——注册真实 `DensityFunction` 子类型，经 `CompileContext`/`ContextBoundSampler` 拿 Cell 数据。**禁止** visitor 模式与 NoiseChunk 字段注入（26.2 旧路已证脆弱）。

**4.5.3 噪声库**：定义 `Grid1D/2D/3D` 三接口，内置 Value/Perlin 风格/Worley/Cubic/Smooth/Layered 实现；全部实现 `DensityFunction` 适配器，可直接进 noise_settings JSON。

**4.5.4 柱体模型**：`WorldColumn` 接口暴露一列的高度/气候/岩层/水位；`ColumnValue` 注册表供 API 消费者查询。仅作为**只读视图**服务命令/API/预览，不作为生成主路径（主路径走密度函数，避免 BigGlobe 自写 Generator 的兼容孤岛）。

**4.5.5 并发与缓存**：
- 缓存：`ConcurrentHashMap` + 过期条目，清理任务注册到服务器 tick 而非独立守护线程；
- 线程池：`ForkJoinPool` 挂服务器生命周期，`MinecraftServer.stop` 时 shutdown；
- 杜绝 UTF 式 ThreadLocal 全局开关——改用在 `GeneratorContext` 上传递的显式参数对象。

**4.5.6 侵蚀模拟**：分形布朗运动初值 → 水力侵蚀 N 次迭代（ droplet 法，迭代数可配）→ 热侵蚀平滑。侵蚀在 Cell 尺度（低分辨率）执行后双三次插值到方块尺度，成本 O(n²) 有界。

**4.5.7 分享码**：JSON → GZIP → Base64 → `TRC1:` 前缀 + CRC32 校验尾。长度上限 8KB，超限报错不截断。

### 4.6 Mixin 最小化清单

| Mixin | 目标 | 必要性 | 备选方案 |
|---|---|---|---|
| MixinCreateWorldScreen | 注入预设选择页 | 无官方扩展点，必须 | — |
| MixinMinecraftServer | 缓存/线程池生命周期挂钩 | 必须 | ServerLifecycleEvents（Fabric API，优先用事件代替） |
| MixinNoiseBasedChunkGenerator | 含水层替换 | 备选 | 优先尝试 noise_settings JSON 直接声明 |
| MixinPlugin | 条件加载兼容 Mixin | 必须 | — |

## 五、地球拟真地貌专项分析

> 用户核心诉求：实现**地球级真实地貌**。本章从地貌学角度拆解目标，指出现有模组为何做不到，并给出可落地的技术路线。

### 5.1 与参考模组的本质差距

地球地貌的灵魂是**因果链**：山脉因板块碰撞而存在，河流因降水与重力而流动，沙漠因雨影而干旱，峡湾因冰川刨蚀后海侵而成。三个参考模组全是**噪声直接决定形态**——山在哪里、河在哪里由噪声函数一次性拍板，没有"为什么"。这正是它们的地形"好看但不真实"的根因：

| 真实地貌要素 | RTF/UTF | BigGlobe | 差距根因 |
|---|---|---|---|
| 山脉成链、沿板块边界分布 | ✗ 噪声随机成山 | ✗ | 无板块构造层 |
| 树枝状水系、流量累积 | ✗ 河流=噪声洼地 | ✗ | 无水系推演，只有"低地" |
| 三角洲/河漫滩/曲流 | ✗ | ✗ | 无流量-沉积概念 |
| 海沟/岛弧/裂谷 | ✗ | ✗ | 无板块边界类型 |
| 方山（Mesa）/单面山 | ✗ | △ 岩层有雏形 | 无岩性差异侵蚀 |
| 冰川 U 型谷/冰斗/角峰 | ✗ | ✗ | 无冰川作用模拟 |
| 喀斯特峰林/溶洞 | ✗ | ✗ | 无溶蚀机制 |

### 5.3 核心设计转变：从"噪声塑形"到"因果推演"

新管线必须先生成**地理因果场**，再让地形成为因果的表达：

```
板块构造 → 大地貌格局（山脉/海沟/高原/裂谷）
    ↓ 地形高度 + 纬度
气候模拟 → 温度场/降水场（雨影、洋流修正）
    ↓ 降水 × 高度 × 坡度
水系推演 → 河网/流量/下切/沉积
    ↓ 岩性 × 气候 × 水
侵蚀改造 → 峡谷/方山/峰林/U 谷/沙丘
    ↓
群系植被 → 气候+土壤的自然结果
```

### 5.4 分层生成管线（L0–L6）

| 层 | 名称 | 输入 | 输出（密度函数场） |
|---|---|---|---|
| L0 | 板块构造层 | 种子 | 板块 Voronoi + 运动向量 + 边界类型场 + 边界距离场 |
| L1 | 大地貌层 | L0 | 基面高度场：山脉链抬升、海沟下切、高原面、裂谷带 |
| L2 | 气候层 | L1 + 纬度 | 温度场、降水场（含雨影/洋流/海拔递减） |
| L3 | 水系层 | L1 + L2 | 流量累积场、河道网络、水位、下切深度场 |
| L4 | 侵蚀层 | L1 + L3 + 岩性 | 改造后高度场（峡谷/曲流/三角洲/U 谷/差异侵蚀） |
| L5 | 岩层地表层 | L4 | 地层剖面（硬度/岩性）、地表覆盖物规则 |
| L6 | 群系植被层 | L2 + L5 | 群系分布、植被密度 |

全部在 **Cell 尺度（4–16 方块/格）计算，双三次插值到方块尺度**，每层输出注册为真实 DensityFunction，可独立被数据包覆写——这延续了 UTF 的 26.3 接入方案，只是密度函数的"内容"从噪声换成了因果推演。

### 5.5 各层关键算法方案

**L0 板块构造**
- 种子 → Voronoi 划分 8–15 个板块，每板块赋运动向量（方向+速率）
- 边界判定：取 Worley F1/F2 两面元，比较运动向量相对分量——相向=汇聚、相离=发散、错动=转换
- 边界距离场 = Worley F2−F1 的函数，缓存于 Cell
- 汇聚再分：陆-陆→褶皱山；陆-洋→俯冲（洋侧海沟+陆侧火山弧）；洋-洋→岛弧

**L1 大地貌**
- 褶皱山脉：距汇聚边界距离的幂次衰减抬升 × 条带噪声（出平行岭谷）
- 海沟：俯冲边界洋侧窄带深下切（细而深，宽 1–3 格 Cell）
- 火山弧/岛弧：沿边界等距取点 + 抖动 → 火山锥列表（锥形函数）
- 裂谷：发散边界带状下陷，内部地垒地堑交替
- 高原：汇聚板块内部大尺度缓抬升，边缘陡坡

**L2 气候**
- 基温 = 纬度余弦 + 海拔递减（每 1000 格 −6.5℃ 可配）
- 降水 = 基础降水 × 水汽输送：设定主风向，沿风向射线对地形高度积分——迎风坡降水加成、背风坡雨影锐减
- 洋流：沿岸带暖流增温增湿/寒流降温减湿（简化：按海岸距离衰减的符号场）

**L3 水系**
- Cell 尺度 D8 流量累积：每格流向最低邻格，迭代至汇口（海/湖）
- 流量 ≥ 阈值 → 河道；河宽/下切深度 ∝ 流量^0.4 × 坡度
- 河口（流量大+坡度≈0+临海）→ 三角洲：沉积抬升 + 汊道分裂
- 硬岩坎（地层硬度突变）+ 河道 → 瀑布标记
- 湖泊：洼地洪水填充至溢流口高度

**L4 侵蚀**
- 水力侵蚀：droplet 法在 Cell 尺度迭代（次数可配，性能开关）
- 热侵蚀：坡度超过休止角 → 物质向邻格转移，迭代收敛
- 冰川侵蚀：温度场 < 雪线且处于谷地 → 谷截面由 V 型改为抛物线（U 型），山巅切削出冰斗/角峰
- 差异侵蚀：侵蚀速率 = f(岩性硬度) → 软岩凹、硬岩凸 → 自然形成方山顶盖、单面山、峰林石柱
- 风蚀/风积：干旱区（降水 < 阈值）+ 主风向 → 沙丘定向排列场

**L5 岩层**
- 地层 = 深度分段函数 + 噪声扰动：表土/沉积岩（水平层理，硬度交替）/变质岩/深板岩
- 岩性场输出硬度，供 L4 差异侵蚀与洞穴壁材质消费
- 喀斯特标记：沉积岩（石灰岩）+ 湿润气候 → 溶蚀开启

**L6 群系**
- 群系 = 温度场 × 降水场 × 高度的查表结果（Whittaker 群系图），边界混合带宽可配
- 植被密度随降水梯度；雪线由温度场直接给出

### 5.6 性能与可行性评估

| 风险 | 评估 | 对策 |
|---|---|---|
| 板块 Voronoi 每区块重复计算 | 中 | Cell 缓存 F1/F2/边界类型，一次计算多层级复用 |
| D8 流量累积是迭代算法 | 高 | 限制在 Cell 尺度（256 格/区块），分块迭代 + 邻块边界缝合；结果入缓存 |
| 雨影射线积分 | 中 | 射线步长 = Cell 尺寸，长度上限 64 格，结果缓存 |
| 多层密度函数叠加采样 | 中 | 每层独立缓存 + ConditionalFlatCache 式惰性求值 |
| 26.3 接入稳定性 | 低 | 每层均为注册 DensityFunction，无 NoiseChunk hack |

### 5.7 路线图修订（在原六期基础上插入地貌专项）

- **一期追加**：L0 板块构造 + L1 山脉/海沟/高原/裂谷（先见大格局）
- **二期追加**：L3 水系（河网/瀑布/三角洲）+ L4 水力/热力侵蚀 + 峡湾海岸
- **三期追加**：L2 气候因果场（纬度/雨影/洋流）驱动群系
- **四期追加**：L4 冰川/差异侵蚀/风成 + L5 岩性 + 喀斯特（P2 项按反馈裁剪）

## 六、三维度重塑 · 高度解放 · 性能工程专项

### 6.1 下界（地狱）重塑

**设计主题：火山与熔岩世界**——把 L0–L6 因果思想做"熔岩版"换皮（算法复用，参数与介质替换）：

|---|---|

**群系与地貌绑定**：玄武岩三角洲 = 柱状节理区；灵魂沙峡谷 = 风蚀峡谷；绯红/诡异森林 = 熔岩台地上的生态岛。下界基岩顶/底层在新高度体系下重映射（见 6.3）。

### 6.2 末地重塑

**已实现（三期首版，见 EndShatteredContinentFunction）**：

**设计主题：碎裂大陆**（后续迭代方向，尚未做）：

- 主岛扩大带地形起伏（山丘、裂谷、内部空腔）
- 外岛多样化：环礁岛、柱岛、层叠岛、岛链

- 紫颂树分布随岛屿形态与"海拔"

**技术接入**：下界/末地在 26.3 同为 `NoiseBasedChunkGenerator` + 独立 noise_settings——复用主世界的密度函数注册方案，三维度各一套因果参数，**不引入第二套生成架构**。接入点即覆写维度 density_function key（下界 `nether/base_3d_noise`；末地 `end/base_3d_noise` + `end/islands`），不触碰 noise_settings，延续最小改动原则。

### 6.3 建筑高度上限解除

**机制分析**：

- 维度高度由 `dimension_type` JSON 数据驱动（`min_y`/`height` 字段），数据包层面即可修改
- 但 `LevelHeightAccessor` 存在硬校验：`min_y ≥ -2032`、`height ≤ 4064`、`min_y + height ≤ 2032`、均为 16 的倍数
- **数据驱动方案的极限为 -2032 ~ 2032（共 4064 格）**；超出需 Cubic Chunks 式区块存储重写——明确不做，属于另一个数量级的工程
- 配套必改：`noise_settings` 全 Y 轴重采样参数、矿石分布、含水层、熔岩面、基岩层、结构生成高度范围全部按新高度重映射；海平面默认保持 Y=63（可配）

**方案：高度档位化**（做成预设选项，用户自选）：

| 档位 | 主世界范围 | 总高 | 定位 |
|---|---|---|---|
| 保守 | -64 ~ 319 | 384 | 原版兼容，与其他模组联动用 |
| 扩展（默认） | -512 ~ 1535 | 2048 | 山峰可上 Y≈1000，拟真雪山/冰川 |
| 极限 | -1024 ~ 2031 | 3056 | 旗舰体验，性能开销最大 |

- 下界/末地同步扩展（下界建议 -256 ~ 767 档位，基岩顶逻辑重写；末地扩展岛屿垂直分布范围）
- 与 L2 气候联动：海拔递减率在新高度下产生真正的雪线、高山草甸带、冰川作用带
- 本项目未发布，无需考虑旧存档兼容（用户已声明）

**代价认知**：高度每翻一倍 → 密度函数采样量、光照引擎、高度图、生物生成尝试次数近似线性增长 → 必须由 6.4 性能工程对冲。

### 6.4 性能工程专项

**原则：优化不是事后补丁，是架构属性。** 贯穿全部子系统的十条红线：

1. **计算尺度下沉**：一切昂贵推演（板块/水系/侵蚀）只在 Cell 尺度执行，方块尺度仅做双三次插值——计算量降为 1/16 ~ 1/256
2. **多级缓存体系**：Cell 缓存 / 板块边界距离场缓存 / 河网结果缓存 / 密度函数 2D flat cache；全部绑定 `RandomState` 生命周期 + TTL + 容量上限，世界卸载全量释放（修复 RTF 系内存泄漏根源）
3. **线程模型**：禁止全局静态线程池（UTF 教训）；复用 MC worker 线程；采样器无状态化或 ThreadLocal 严格隔离；禁止 ThreadLocal 全局开关——上下文一律经 `GeneratorContext` 显式传参
4. **惰性求值**：ConditionalFlatCache 式——NoiseRouter 实际不采样的分支不计算
5. **区域异步预处理**：板块场/河网以 Region（32×32 区块）为单位后台预计算 + 缝合，可选落盘缓存
6. **算法复杂度红线**：禁止 O(n³)；侵蚀迭代次数封顶可配；D8 流量累积分块迭代
7. **高度扩展对冲**：密度采样按 cell 垂直分辨率而非逐格；地表规则轻量化；含水层按地表高度限界查询（VolumeAquifer 思想）
8. **性能配置**：PerformanceConfig 三档质量（侵蚀迭代数 / 缓存容量 / 河网密度 / 预处理半径），Cloth Config 界面，zh_cn/en_us 同步
9. **兼容协同**：声明 C2ME 线程安全（不 hack 其内部）；DistantHorizons 采样路径保证密度函数可重入
10. **基准与回归**：单区块生成耗时预算 ≤ 原版 1.5×；测试套件含性能基准（参考 UTF LandformPerformanceTest）与内存泄漏回归（反复进出世界巡检）

### 6.5 路线图二次修订（以此为准）

2. **二期（水文地表）**：L3 水系 + L4 水力/热力侵蚀 + 地层 + 地表规则 + 海岸 + **下界重塑**

## 七、群系 · 结构 · 矿石 · 第三方兼容专项

> 追加需求：群系生成合理化；结构分布均匀且好找；矿石资源分布均匀且好找；对添加群系/结构的第三方模组保持高兼容。

### 7.1 群系生成深化

**原版机制**：26.3 群系由 `MultiNoiseBiomeSource` 以六维气候参数点（温度/湿度/大陆性/侵蚀/深度/怪异度）查表放置——参数本身是噪声，无地理因果，且第三方群系模组必须挤进同一参数空间，互相挤压出"马赛克群系"。

**本模组方案**：
- L6 群系层以 L2 气候因果场（纬度温度带 + 雨影降水 + 海拔修正）驱动，按 Whittaker 群系图查表——群系是气候的**结果**，与地形天然一致（雪山上必然雪原、雨影背风坡必然干旱）
- 过渡带混合：群系边界设可配宽度混合带，杜绝硬切边
- 深度/洞穴群系独立通道：溶洞/深暗之域按岩性与深度放置，不受地表气候干扰

### 7.2 结构分布（均匀且好找）

**原版痛点**：structure set 的 spacing/separation 是**带抖动的网格随机**——数学上不保证最小间距，实测出现村庄三连扎堆或千格真空；定位指令同步扫描卡主线程。

**本模组方案**：
1. **地理适宜性放置**：结构绑定地貌逻辑——村庄优先平原/河岸阶地；沙漠神殿在沙漠高地；海底神殿邻近海沟；林地府邸在 mature 森林腹地。结构不再是"随机撒点"，而是"长在合适的地貌上"
2. **Poisson 盘均匀化**：放置采样改用 Poisson-disc（保证最小间距的均匀分布），配合区域配额——每个 Region（32×32 区块）保底结构配额，消灭真空区
3. **好找性**：
   - `/terrainrecast locate` 全异步（借鉴 BigGlobe AsyncLocateCommand），主线程零卡顿
   - 结构放置校验：不埋于地下、不悬浮半空、入口朝向可达
   - 结构密度进配置，整合包可调
4. **数据驱动**：structure set 全走数据包 JSON，本模组不改原版注册管线

### 7.3 矿石资源分布（均匀且好找）

**原版痛点**：矿石 = 纯 RNG 的 configured feature——富集区与贫瘠区全凭运气；深层矿完全盲挖。

**本模组方案：地质逻辑矿床**（矿在哪由地质决定，而非纯随机）：

| 矿床类型 | 地质原型 | 对应矿物 | 可发现性线索 |
|---|---|---|---|
| 层控矿床 | 沉积层伴生 | 煤、铁（特定地层条带富集） | 岩层断面可见夹层 |
| 热液矿脉 | 构造带热液充填 | 金、铜（板块边界/火山弧附近富集） | 断层崖/火山附近石英脉露头 |
| 金伯利岩筒 | 深源岩浆通道 | 钻石（深部垂直筒状富集） | 地表指示性矿物风化斑 |
| 砂矿 | 河流冲积富集 | 金、铁砂（河床/三角洲） | 河床淘洗层 |

- **均匀性保障：区域配额制**——每个 Region 有矿石预算下限，生成时按预算校准，数学上消灭贫瘠区
- **好找性保障：地表露头**——矿脉延伸至近地表时生成风化露头（少量对应矿石+伴生岩），玩家地表探矿 → 顺藤摸瓜，替代盲挖
- 下界矿石同逻辑重做（远古残骸绑定"熔岩管壁"，石英绑定热液区）
- 全部数据驱动：矿床类型/丰度/高度区间/伴生岩走数据包 JSON，整合包与附属模组可增删矿床类型

### 7.4 第三方群系/结构模组兼容

**矛盾本质**：自定义群系源 + 自定义地形意味着其他群系模组的"默认注入通道"失效。兼容策略分四层：

1. **预设隔离（底线）**：本模组生成器仅在自己注册的世界预设下激活，走数据包 `worldgen/world_preset` JSON——未选本预设时模组对生成管线**完全惰性**，原版与其他模组世界不受任何影响
2. **TerraBlender 双轨（主通道）**：TerraBlender 是 Fabric 生态多群系模组共存事实标准——本模组注册为 TB Region，TerraBlender 系群系模组（BYG/BOP 类）自动注入我们的气候参数空间，无需逐个适配
3. **自研群系注入 API（副通道）**：非 TB 模组可通过 `TerrainRecastApi` 声明群系的气候需求（温度/湿度/海拔区间），由我们的气候采样器统一分配——比挤参数点更符合直觉
4. **结构与特征兼容**：不改原版 structure/feature 注册管线 → 结构模组（Repurposed Structures 类）与 Fabric BiomeModification API（特征/生成物注入）天然不受影响

**实施约束**：TerraBlender 兼容走条件 Mixin + MixinPlugin（参考 UTF 模式），独立配置开关；TB 缺席时自研 API 独立可用，不形成硬依赖。

### 7.5 路线图三次修订（以此为准）

1. **一期（骨架）**：Cell 引擎 + 密度函数接入 + 高度档位化 + L0 板块 + L1 大地貌（主世界）+ datagen
2. **二期（水文地表）**：L3 水系 + L4 水力/热力侵蚀 + 地层 + 地表规则 + 海岸 + **矿石分布（随 L5 地层联动）** + 下界重塑
3. **三期（气候群系）**：L2 气候因果场 + **L6 群系 + 结构地理适宜性放置 + TerraBlender 双轨** + 末地重塑
4. **四期（植被地物）**：程序化树木 + 地物 + 冰川/差异侵蚀/风成/喀斯特（P2 裁剪）
5. **五期（交互）**：预设 GUI + 分享码 + 命令（含异步 locate）+ 配置界面
6. **六期（生态与性能）**：兼容层补全 + 附属模组 API + 测试套件 + 性能专项调优与基准验收

## 八、拓展空间 · 社区附属 API 专项

> 追加需求：内置 API 供社区开发附属模组；盘点其余可拓展与可优化方向。本章仅设计，不动代码。

### 8.1 社区附属模组 API（Terrain Recast API）

**设计目标**：把模组从"一个地形包"升级为"一个地形平台"。

**三条铁律**：
1. **API/实现分离（DIP）**：`yifei.terrain.recast.api` 包只含接口、数据类型、注解，零实现类；附属模组只依赖 api 包 → 内部实现可自由重构不破坏生态（RTF/UTF 的教训：内部类被附属直接引用，一改即崩）
2. **注册口而非修改口（OCP）**：每个子系统暴露注册表/管线钩子，附属模组"加东西"而非"改东西"
3. **异常隔离**：附属模组的事件监听/注册回调抛异常时，捕获、记日志、跳过——绝不让一个附属崩毁主生成管线

**API 面（九大注册/查询口）**：

| API | 内容 | 消费场景 |
|---|---|---|
| `TerrainRecastApi` 入口 | 服务获取、能力查询、版本协商 | 一切附属模组入口 |
| Cell 查询 API | 只读 CellData 视图（高度/气候/侵蚀/板块/岩性/流量/地貌类型） | 农业气候、体温、寻路类模组读地理数据 |
| ColumnValue 注册表 | 借鉴 BigGlobe：附属注册自定义列值并暴露 | 数据查询互通 |
| 密度函数管线钩子 | 附属注册自定义密度函数层，插入 L0–L6 指定层位（前置/后置） | 加魔法地形层、异星改造层 |
| 地貌类型注册 | 自定义 Landform（含判别函数+生成参数）参与 L1–L4 | 加浮空岛、蘑菇大陆等地貌 |
| 群系注入 API | 声明气候需求区间（温度/湿度/海拔），气候采样器统一分配（7.4 副通道） | 非 TerraBlender 群系模组 |
| 矿床类型注册 | 自定义矿床类型（判别条件/丰度/高度/伴生岩/露头样式） | 科技模组加自己的矿 |
| 结构适宜性 API | 结构模组声明适宜地貌/气候/坡度，接入地理适宜性放置（7.2） | 结构模组生成不再瞎放 |
| 预设扩展 API | 附属以数据包发布预设 + 注册自定义 Option 类型进预设 GUI | 整合包/预设作者 |

**配套机制**：
- Fabric entrypoint `terrain_recast`：附属模组声明式接入，保证加载顺序在注册表冻结前
- 事件总线：`PreCellCompute` / `PostErosion` / `PreSurfaceApply` / `ChunkDecorate` 等生成阶段事件，监听器异常隔离
- API 语义化版本：`@ApiStatus.Experimental`/`@Stable` 标注，破坏性变更只随大版本
- 数据驱动优先：能用数据包 JSON 表达的（预设/矿床/树木参数包）不走代码 API——降低附属开发门槛

### 8.2 其余可拓展方向（按价值排序）

| 方向 | 说明 | 取舍 |
|---|---|---|
| 种子/地形预览器 | 创建世界界面内嵌小地图预览（接 WorldPreview 或自研采样渲染） | 高价值，入五期 GUI |

### 8.3 可再优化的点（对第六/七章的补充）

4. **事件分发开销**：无监听器的事件直接短路跳过，不构造事件对象

## 九、结论

新模组以 **UTF 的 26.3 原生密度函数接入为骨架、RTF 的 Cell 引擎为血肉、BigGlobe 的柱体抽象与噪声库为工具**，剔除脚本引擎（以 Codec/JSON 数据驱动替代）、剔除玩法捆绑、以生命周期绑定的并发模型修复两 RTF 系的内存隐患，以"Mixin ≤ 5 + 官方注册表优先"策略修复版本升级脆弱性。

面向"地球真实地貌"目标，核心升级是**用 L0–L6 因果推演管线替换噪声塑形**：板块构造决定山脉海沟之"所在"，气候与水系推演决定河流沙漠之"所以"，岩性差异侵蚀雕刻方山峰林之"形态"——让每一处地貌都有地理学上的成因。这在国内外国产地形模组中尚无完整实现，是 Terrain Recast 的差异化灵魂。

### 10.2 核心增量发现（改变设计决策）

#### 10.2.1 Lithostitched · DataModifier 管线 > 自研事件总线

**架构**：Lithostitched 是 architectury 多版本世界生成库模组（common/shared/{21.1,26.1,26.2}/fabric/neoforge 多版本源码集），核心是一套声明式 DataModifier 体系：

```java
// worldgen/modifier/WrapDensityFunctionModifier
// 数据包 JSON: { "type": "lithostitched:wrap_density_function", "target": "...", "modifier": "..." }
public interface Modifier {
    void modify(LithostitchedContext context);
}
```

所有 Modifier 分四大类：
- `Add*Modifier`（AddStructureTemplates / AddSurfaceRule / AddProcessorListProcessors / AddTemplatePoolElements）
- `Remove*Modifier`（RemoveStructureSetEntries）
- `Set*Modifier`（SetPoolAliases / SetStructureSpawnCondition / SetPoolElementProcessors）
- `Wrap*Modifier`（WrapDensityFunction / WrapNoiseRouter）

**LoadPredicate 条件启用**（比事件监听器更精确）：
```java
public sealed interface LoadPredicate permits ModLoadedPredicate, LoaderPredicate, PackFormatPredicate, AllOfPredicate, AnyOfPredicate, NotPredicate {

```

**duck interface 替代硬 Mixin**：`StructurePoolAccess` / `MNBSDuck` / `NoiseChunkAccessor`——只在确实拿不到的私有成员上用 duck，能走官方接口就走官方接口。

**对 TRC 的决策影响**：
- ~~第八章 8.1 节事件总线（PreCellCompute / PostErosion / PreSurfaceApply）~~ → **替换为 DataModifier 管线**
- 附属模组用**数据包 JSON 声明式接入**，比写 Java 监听器门槛低一个数量级
- TRC Mixin 预算 ≤ 5 可进一步压到 ≤ 3（只做必要 duck 接口：Cell 查询视图的生命周期安全包装）
- 架构调整：在 L0–L6 管线的每个层位暴露 `LithostitchedContext` 风格的修改口

#### 10.2.2 Tectonic · ConfigConstant / ConfigNoise 证明"预设值=密度函数"直接可行

两个关键类（`dev.worldgen.tectonic.worldgen.densityfunction` 包）：

```java
// ConfigConstant：字符串 key → 配置值 → DensityFunction 节点
public record ConfigConstant(double value) implements DensityFunction {
    public static MapCodec<ConfigConstant> DATA_CODEC = Codec.STRING.fieldOf("key")
        .xmap(ConfigConstant::new, df -> "");
    public ConfigConstant(String key) {
        this(ConfigHandler.getState().getValue(key));
    }
}

// ConfigNoise：把配置 scale 作为参数注入噪声偏移
public record ConfigNoise(NoiseHolder noise, DensityFunction shiftX, DensityFunction shiftZ, double scale) implements DensityFunction {
    public ConfigNoise(String key, ...) {
        this(noise, shiftX, shiftZ, ConfigHandler.getState().getValue(key));
    }
}
```

**关键观察**：ConfigHandler.getState() 返回的是当前世界配置状态——说明这个模式**是世界级、线程安全、生命周期绑定的**，不是全局静态。

**对 TRC 的决策影响**：
- ~~第四章 G1 预设"预设→Cell 字段→密度函数"中间桥接层~~ → **直接用 ConfigConstant 模式**
- 预设里的每个数值选项（大陆性/山脉高度/侵蚀强度/海岸线偏移）本身就是一个 DensityFunction 节点，插进 NoiseRouter
- 预设 = 数据包资源 + ConfigHandler 当前状态 → 生成链零额外桥接
- ConfigHandler 必须是**世界级（MinecraftServer 持有）、生命周期绑定**的——杜绝 UTF 那个 ThreadLocal 全局开关问题

#### 10.2.3 YUNG x2 · "注册级禁用 + tag 重定向"是替换原版结构最干净的策略

**yungs-better-strongholds** 整个模组只有 **1 个 Mixin**：


但这其实是**过度保守**——**Lithostitched.RemoveStructureSetEntriesModifier 可以纯数据包移除原版 structure_set 条目**，不需要 Mixin。YUNG 用 Mixin 是因为它不依赖 Lithostitched。


末影之眼 tag 重定向：


**对 TRC 的决策影响**：
- 想替换原版要塞/废弃矿井？**优先走 Lithostitched Modifier 管线**（RemoveStructureSetEntries + 自己的 structure_set），Mixin 留作兜底
- Tag 重定向是**官方注册点范围内的纯数据注入**，零 Mixin
- YUNG 自定义的 `BetterStrongholdsPlacement extends RandomSpreadStructurePlacement`（环形分布 + chunkDistanceToFirstRing / ringChunkThickness / maxRingSection）——TRC 可以借鉴自定义 `StructurePlacement`，让结构按地理类型成组分布（山脉节点有要塞群、平原带村庄群）

### 10.3 重要增量发现（强化之前设计决策）

#### 10.3.1 TerraBlender Region + ClimateBridge 解决自定义群系兼容难题

TerraBlender 为自定义群系模组提供 Region 扩展点，把附属的 `Climate.ParameterPoint → Biome` 映射追加进原版 `MultiNoiseBiomeSource` 的 RTree 空间（L59-148），未覆盖区域用 `DEFERRED_PLACEHOLDER` 回退原版。

TRC 的挑战：L6 Whittaker 图用的是**六维气候**（纬度/海拔/湿度/侵蚀/怪异度/大陆性），原版 Climate.Parameter 是**七维**（temperature/humidity/continentalness/erosion/depth/weirdness/offset）。

**解决方案**：新增 `ClimateBridge`——TRC 六维气候采样 → 近似映射到原版七维（大陆性=continentalness，侵蚀=erosion，海拔近似 depth，湿度=humidity，怪异度=weirdness，温度由纬度+海拔合成 → temperature），让 TerraBlender 正常工作。TRC 自己的群系走 Whittaker 图，对第三方群系透明桥接。这个桥接类属于 `worldgen/climate` 包。

#### 10.3.2 TFC GenLayer 管线 · 独立数据层 + BMP 调试可视化

`GenLayerTFC.initialize()`（L27-81）展示了两个独立管线**在末端合并**的模式——大陆/群系管线和河网管线各自独立 zoom/smooth，最后 `RiverMix` 合并。所有数据层（Rain/Rock/PH/Stability/Drainage/Tree）也是独立管线。

每层结束后调用 `drawImage()` 生成 BMP，**离线可视化地形生成各阶段**——这个调试习惯值得 TRC 继承。

**对 TRC 的影响**：
- L0–L6 管线本来就是各层独立推演 → TFC 用 GenLayer，TRC 用 DensityFunction，本质同构
- 新增 **调试 BMP 输出开关**（开发版启用、发布版关闭）：板块边界/侵蚀量/河网/Whittaker 群系各生成一张 2D 图
- 河网管线**独立于大陆层**（D8 流量累积是纯水文推演，不依赖 Cell 地形高度以外的东西）
