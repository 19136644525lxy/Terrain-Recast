## 1. 现在能跑通什么（都已实测验证）

### 1.1 地形

- `RealCellLookup` 用 Worley 板块 + 连续噪声出：大陆度、山脊、海沟、次级起伏。
- `Cell.Field.TERRAIN_HEIGHT` 走 `depth` 覆写进入密度函数，决定地表高度。
- P0 校准后（seed 1）高度分位：**p50 ≈ 270、p90 ≈ 570、max ≈ 960**，
  坡度 p50 ≈ 1.5、max ≈ 7.5，海洋占比 14%。

### 1.2 大地貌（L1）

| 地貌 | 编码 | 生成规则 | 地形效果 |
|---|---|---|---|
| 裂谷 | -0.6 | 张裂边界带 × 边界接近度 > 0.30 | 沿边界下切 75 格 |
| 火山弧 | 0.7 | 汇聚边界带 × 边界接近度 > 0.30 | 沿边界抬升 210 格，串珠山链 |
| 高原 | 0.35 | 板块内部 × 低频分布 > 0.45 | 向台面 210 格收敛并压平 |
| 平原 | 0.0 | 其余陆地 | 无 |

三个掩码（`riftMaskAt` / `arcMaskAt` / `plateauMaskAt`）**地形塑形与群系分带共用**。

### 1.3 群系

- 24 个自定义群系：`terrain_recast:<plains|plateau|rift|arc>_<tundra|taiga|grassland|forest|desert|savanna>`
- 命名：`biome.terrain_recast.*` 已在 `zh_cn` / `en_us` 补齐（如「裂谷针叶林」/ `Rift Taiga`）
- 颜色：`effects` 里的 `#RRGGBB`（26.3 仍在这里，**不需要** `attributes`）
- 地表规则：`material_rule/overworld.json` 最前面两条按群系条件
  （`BiomeCondition.biome_is`）——arc 系列 → 玄武岩，desert 系列 → 沙子
- 原版/自定义混合：`Cell.Field.BIOME_FAMILY`（700 格噪声）驱动 `overworld/erosion`，
  表里 `erosion < 0` 进原版族、`≥ 0` 进自定义族。实测正负比 57.6 / 57.2 / 54.3 / 39.6 %，
  平均约 52%

### 1.4 地物注入

- `VegetationWorldgen` / `OreDepositWorldgen` 通过 `GroupedFeatureInjection` 登记，
  由 `TerrainRecast.onInitialize()` 末尾统一 `apply()`。
- 选择器 `TRC_BIOMES`：**只注入 `terrain_recast` 命名空间的群系**。
- 自定义群系依赖 `data/minecraft/tags/worldgen/biome/is_overworld.json`
  （`replace: false` 合并）才会被 `BiomeModifications` 命中。

## 3. 数据包覆写清单（改动都在这里）

| 路径 | 作用 |
|---|---|
| `data/minecraft/worldgen/noise_settings/overworld.json` | 6 个 router 字段指向 `terrain_recast:cell_field` |
| `data/minecraft/worldgen/density_function/overworld/{depth,erosion,ridges,continents,temperature,vegetation}.json` | 把 router 接到 Cell 字段 |
| `data/minecraft/dimension/overworld.json` | **内联 `multi_noise` 群系表**（32 条）。原版 overworld 的 dimension 是代码定义的，覆写这个路径即整体替换 |
| `data/minecraft/dimension_type/overworld.json` | 高度 -512..2032 |
| `data/minecraft/worldgen/material_rule/overworld.json` | 地表规则；最前面是群系条件规则 |
| `data/minecraft/tags/worldgen/biome/is_overworld.json` | 把自定义群系并入主世界标签（地物注入的前提） |
| `data/terrain_recast/worldgen/biome/*.json` | 24 个群系定义 |

**参数怎么流到群系选择**：

```
Cell.Field.X  →  cell_field 密度函数  →  router 字段  →  群系表的 6 个参数
```

- `temperature` ← `TEMPERATURE`（纬度 + 抖动 + 海拔递减）
- `humidity` ← `MOISTURE`
- `continentalness` ← 解析基面高度（海陆）
- `erosion` ← **`BIOME_FAMILY`**（群系族选择器，正负分族）
- `weirdness` ← **`LANDFORM`**（地貌编码，四段分带）
- `depth` ← `TERRAIN_HEIGHT`（地形）

> 注意：router 里的 `erosion` 已经被改造成**群系族选择器**（`BIOME_FAMILY`）。
> 而 `Cell.Field.EROSION`（山脊型侵蚀度）仍然存在，并且**被矿床地物消费**
> （`TerrainOreDepositFeature` 按侵蚀度分带布矿），所以两个概念现在是分开的：
> 一个是"群系族开关"，一个是"地质侵蚀度"。

## 4. 踩过的坑（最重要的一节）

### 4.1 26.3 的 API/格式变化

| 项 | 旧写法 | 26.3 |
|---|---|---|
| `ResourceKey` 取 id | `location()` | **`identifier()`** |
| 群系 `carvers` | `{"air": [...]}` | **扁平列表** `["minecraft:cave", ...]` |
| 群系 `features` | 任意长度 | **必须 11 个装饰步骤**，缺一段解析失败 |
| 群系颜色 | `#RRGGBB` | 仍是 `#RRGGBB`，在 `effects` 里（不是 `attributes`） |
| 高度图（未生成区块） | — | `getHeight()` 返回 **-512**（minY），不是 0 |
| 区块事件 | `CHUNK_GENERATE` | `CHUNK_LOAD(ServerLevel, LevelChunk, boolean)` |
| 高度提供器 | `{"absolute": y}` 之外 | `VerticalAnchor` 必须写 `{"absolute": y}` |
| `RandomState` | 有 `sampler()` | 只有 `createClimateSampler(SamplerContext)`，**拿不到现成 sampler** |

### 4.2 群系表

- **必须覆盖整个参数空间**。任何采样点落在所有表项之外会直接抛错。
  本项目的做法：所有不参与分带的参数一律写 `[-2, 2]`。
- 表项范围**重叠**时按顺序取第一个匹配，所以顺序即优先级。
- 原版 overworld dimension 是**代码定义**的，不在数据包里；要替换群系源只能
  覆写 `data/minecraft/dimension/overworld.json`（内容要写全 generator + settings）。

### 4.3 地物与标签（两个真实事故）

**事故 A：自定义群系完全没有植被。**
根因：植被靠 `BiomeModifications` + `BiomeTags.IS_OVERWORLD` 注入，自定义群系
不在这个标签里 → 一条地物都没进去。
修法：`data/minecraft/tags/worldgen/biome/is_overworld.json`，`replace: false` 合并。

**事故 B：`Feature order cycle found`。**
现象：区块生成直接抛
`Feature order cycle found, involved sources: [terrain_recast:rift_taiga, minecraft:plains]`。
两个原因叠加：
1. 同一批 placed feature 同时注入原版群系和自定义群系；
2. 自定义群系 JSON 里手写的原版地物（`ore_coal_upper`、`patch_grass_plain` …）
   与 vanilla 群系里的相对顺序不一致。

修法：TRC 地物只注入自定义群系（`TRC_BIOMES` 选择器）＋ 清空 24 个群系 JSON 的
`features`（全走注入）。

### 4.4 验证手段的坑

- **不要在 `SERVER_STARTED` 里同步生成大量区块**：441 个区块触发了服务器
  watchdog（单 tick 超 60 s 强制关服）。9 个区块没问题。
- 想统计群系占比，最好走离线（`dumpPreview`），或者小样本探针；
  直接采样 `BiomeSource` 在 26.3 拿不到 `Climate.Sampler`。
- `dumpPreview` 的 `landform`/`biome` 图只反映**我们的字段**，不等于实际群系；
  实际群系要用实机探针（读 `level.getBiome(pos)`）验证。

### 4.5 构建 / 编码 / git

- Gradle 判定 UP-TO-DATE 时**不会刷新 jar 时间戳**。要新 jar 用
  `--rerun-tasks`（不是 `clean`，项目规范禁止随手 clean）。
- PowerShell 控制台显示中文乱码**不代表文件坏**（是控制台编码）。
  写文件用 `[System.IO.File]::WriteAllText(path, text, UTF8Encoding($false))` 避免 BOM。
- PowerShell 里 `-replace` 用字符串拼接很容易出错，多行 JSON 建议直接整文件重写。
- 仓库里 `temp/`（第三方模组源码）、`build/`、`run/`、`crash/`、`server_*.txt` 都在
  `.gitignore` 里；提交前 `git status` 确认没混进去。

### 4.6 水系为什么失败（已下线，但教训要留）

做过的尝试与结论：

1. **"按列堆水"**：`水面 = 地形面 + 下切深度` → 陡坡上变成一格一级的碎台阶。
2. **改成按格绝对水面**：台阶变粗，但**这片地形不随 h 抬升**
   （实测 `Y ≈ 263 − 0.031·h`，h 跨 380 格地面只动 20 格），
   于是 h 差值被当成方块数直接加到地面上 → **几十格高的水墙**，村庄树全淹。
3. **改成"自己挖再灌水"**（参考 `streams`）：把最高的 2~4 格实心方块换成水。
   技术上可行，但用户最终决定整体下线。

**如果以后要重做，先解决这个前提**：`depth` 覆写在某些区域被密度样条压平，
导致 L3/L4 的下切和侵蚀在那里**根本没有效果**。不修这个，水系只能"挖水渠"。

### 5.1 山脉是怎么生成的

高度由 `RealCellLookup.baseTerrainHeight()` 一项项叠出来：

```
h = 海陆基底 + 山脉抬升 − 海沟 + 次级起伏 + 侵蚀填谷
    + 高原/裂谷/火山弧 的地貌修正
```

其中山脉抬升是：

```java
ridge  = 1 - |fbm(x, z, MOUNTAIN_SCALE=620, 3 个八度)|   // ridged 噪声，脊线尖锐
massif = smoothstep(fbm(x, z, 1600) * 1.1 + 0.15)        // 板内山系掩码 0~1
broadMask = smoothstep(massif * 1.5 - 0.45)              // 只有约三成区域能成"山块"

// 瘦山：窄造山带（edge^6）× 尖锐脊线（ridge³）→ 阿尔卑斯式刃脊
sharpMass = edge^6 * (1.00 + 0.35*arc) * ridge³
// 胖山：宽造山带（可伸进板内）× 低频山块 × 平缓脊线 → 高原式山体
broadMass = broadMask * (0.30 + 0.70*edge) * (0.75 + 0.25*arc) * (0.55 + 0.45*ridge)
// 板内零星山系
intraplate = (1 - edge) * massif * 0.10

uplift = landness * clamp(sharpMass + 0.78*broadMass + intraplate, 0, 1.25)
         * mountainAmp * sharpness * verticalScale
```

- `landness`：大陆度 0（深海）~1（内陆），山脉只长在陆地上
- `edge`：板块边界接近度 0~1
- **两种山必须同时存在**：只有 `edge^6 × ridge³` 时全图都是刀片山，没有体量；
  加上 `broadMass`（宽带 + 低频山块 + 平缓脊线）才有青藏式的高原山块
- `sharpness`：`1 - erode*erosionRound`，老年地貌把山脊磨圆
- `mountainAmp`：配置项 `terrain.mountain_amp`，现值 **1100**
- `verticalScale`：配置项 `terrain.vertical_scale`，现值 **1.0**（主高度倍率，参考 TerraForged 的 `globalVerticalScale`）

> **关键坑（三轮才修对）**
> 1. 旧公式 `(0.45 + 0.55*edge) * (0.8 + 0.9*massif)`：板内保留 45% 基础抬升 → 全世界都是山。
> 2. 只改权重不够——`PLATE_CELL_SIZE` 原为 **384**，`EDGE_SPAN = 0.55×384 ≈ 211`，
>    而 384 的板块网格意味着**七成面积都在边界带里**。放大到 **900**、`EDGE_SPAN = 0.30×900 = 270`
>    之后边界才真正稀疏。
> 3. 收窄过头会只剩瘦山：`edge^6 × ridge³` 把山压成刀片，必须补一路 `broadMass`。
>
> **调参时务必固定种子**（`run/server.properties` 里 `level-seed`）：
> 每次 `runServer` 都是随机种子，覆盖率会跳 ±50%，很容易误判。

实测（seed=12345，半径 4000 格点统计）：

| 指标 | 数值 |
|---|---|
| 陆地中 h>200 占比 | 17.9% |
| h>300 | 12.3% |
| h>500 | **6.8%** |
| h>800 | **2.5%** |
| h>1000 | **1.0%** |
| 半径 12000 内最高峰 | h=1712（另有 1655 / 1646） |

`h>500` 到 `h>800` 之间那 4.3% 就是"胖山"的山体（宽缓的高原面），
`h>1000` 的 1% 是瘦山的脊顶——两种形态的面积比约 **4:1**。

### 5.2 高度上限与"平顶山"的坑（重要）

`depth` 覆写里的 y 梯度只覆盖 **Y = −512 … 2031**：

```
depth = gradient(-512→1.5, 2031→−1.5) + (−0.8217) + h × 0.0011797
```

`h` 是相对海平面的高度，`h × 0.0011797` 这一项把地表往上推。当 `h` 超过约 **1968**，
整列的 depth 都会是正值 → 地形变成**实心到建筑上限**（不是"很高的山"，是一堵石墙）。

修法：在 `baseTerrainHeight()` 末尾做**软膝压缩**（不是硬截断，否则会出现一片
1860 的平顶山）：

```java
if (h > 1200) h = 1200 + 660 * (1 - exp(-(h-1200)/660));   // 渐近到 1860
```

实测峰值：半径 2000 → h≈1380、6000 → 1696、12000 → 1756（地表 Y ≈ 1440 / 1760 / 1820）。

> **为什么"千格以上的山难找"**：`ridge` 只在噪声过零且梯度大的地方接近 1，
> 同时要求 `edge` 高（板块边界附近）且 `landness` 高（不能在海岸）。
> 三个条件同时满足的地方面积占比很小，但**确实存在**，用下面的命令能直接定位。

### 5.2b 【重要】高度场曾经根本没接进地形（2026-10-27 修）

**症状**：`/terrainrecast peak` 报出 `h=1528`（预期 Y≈1591），`tp` 过去只有 200 多格的坡；
采样 h 与真实地表 Y 完全对不上（h=1662 → Y=254、h=311 → Y=244、h=-69 → Y=63）。

**根因**：高度是通过 `depth` 注入的，而原版的 `sloped_cheese` 是：

```
sloped_cheese = 4 · quarter_negative((depth + jaggedness) · factor) + base_3d_noise
```

其中 `factor` / `jaggedness` / `offset` 都是**由 `erosion` / `ridges` 驱动的样条**。
而我们为了群系分带，把 `erosion` 改成了 `BIOME_FAMILY`、`ridges` 改成了 `LANDFORM`
——样条拿到的是无意义的值，`depth` 项被压掉，地形退化成 `base_3d_noise`（≈255 平坦）。

**排查手法**（很好用）：把可疑的 DF 换成常量，看地形变不变。

- `depth = -5.0` → 地形塌到海平面 63：说明 `depth` 确实被使用
- `depth = gradient + 1000` → 地形仍是 255：说明 `depth` 的**加法项被样条吃掉**
- 覆写 `sloped_cheese` 无效（该条目是代码注册的，数据包覆盖不了）

**修法（照 Tectonic）**：不让 router 用原版的 `final_density`，改成指向我们自己的 DF：

```
noise_settings.noise_router.final_density = terrain_recast:terrain/final_density
noise_settings.noise_router.initial_density_without_jaggedness = terrain_recast:terrain/heightfield
```

```jsonc
// terrain_recast:terrain/heightfield —— 高度场（y = 63 + h 处密度过零）
{ "type": "minecraft:squeeze",
  "input": { "type": "minecraft:mul", "left": 0.05, "right":
    { "type": "minecraft:add",
      "left": { "type": "minecraft:add", "left": 63.0, "right": "terrain_recast:landform_height" },
      "right": { "type": "minecraft:mul", "left": -1.0, "right": { /* y = gradient(-512→-512, 2031→2031) */ } } } } }

// terrain_recast:terrain/final_density —— 保留原版的空腔与基岩项
{ "type": "minecraft:add",
  "left": { "type": "minecraft:min",
            "left": "terrain_recast:terrain/heightfield",
            "right": "minecraft:overworld/caves/noodle" },
  "right": { "type": "minecraft:beardifier" } }
```

### 5.2c 洞穴与性能（2026-10-27 实测）

**洞穴**：试过把原版 `final_density`（5000 字节，含 cheese caves / entrances /
pillars / spaghetti）整份拷来、只把 `sloped_cheese` 换成我们的 heightfield——
结果**高度映射又失效**（h=1559 → Y=255），因为原版那套 `squeeze(interpolated(
blend_density(...)))` 的包裹会把我们 heightfield 的量级压掉。
最终保留简化版 `final_density`（heightfield + noodle + beardifier），
实测地下空气格 870–1635/区块，**洞穴仍然存在**，来源是：

- 原版 `caves/noodle`（意面洞穴）
- 生物群系自带的 **carver**（`minecraft:cave` / `canyon`，群系 JSON 里的 `carvers`）

没并回来的是 cheese caves / cave entrances / pillars。要加，得把它们接进
`final_density` 的 min 链，而不是整份替换。

**性能实测**（`runServer`，25 个区块冷启动）：

| 指标 | 数值 |
|---|---|
| 区块生成 | **127 ms/个**（2544 高） |
| 启动到 Done | 1.5–2.2 s |
| `/terrainrecast peak` 半径 2 万 | **11 ms** |

**结论：慢的原因是世界高度，不是我们的代码。** 高度 2544 是原版 384 的 **6.6 倍**，
区块体积同比例，127 ms ≈ 6.6 × 原版（约 20–30 ms）。验证过两个反例：

- 把 `noise_settings.noise.height` 改成 384 → 区块生成降到 **57 ms**，
  但地形直接消失（Y=−127）：**`noise.height` 必须等于世界高度**
- 给 `final_density` 套 `interpolated(4,8)` → 反而 156 ms，且洞穴几乎消失

要真正提速只有降世界高度（`dimension_type.height`），代价是山峰上限下降：
高度 1536 时地表最高约 Y=1200（h≈1140），仍能出千格山。

**命令加固**：
- `preset apply` / `preset import` 会写配置，已加权限要求（`COMMANDS_GAMEMASTER`，等级 2）
- `info` / `peak` 只读，任何玩家可用；`peak` 半径上限 20000，采样点固定约 96×96，
  耗时与半径无关（11 ms）

**验证**：采样 h 与真实地表 Y 现在一致（h=1490→Y=1555，h=510→Y=574，
h=1327→Y=1392，误差 ≤ 9 格，来自 `squeeze` 的过渡带）。

**代价**：洞穴只剩 `noodle`（原版的 cheese caves / entrances / pillars 没并进来），
以后想恢复洞穴多样性，把 vanilla `final_density` 里的那几项搬进我们的 `final_density` 即可。

### 5.3 参考模组的四种做法（对比）

| 模组 | 高山的实现方式 | 可借鉴点 |
|---|---|---|
| **Terralith** | 覆写 `offset` / `factor` / `jaggedness` 样条，按 continentalness 给整片区域设高度 | 大尺度样条决定"整片高地" |
| **Tectonic** | 完全重写 `final_density`，用 `squeeze` + `upper_slope` 高度场 | 高度场与噪声解耦 |
| **TerraForged（ultraterraforged）** | 每种地貌（含 mountains，weight=2.0）各有 `baseScale/verticalScale/horizontalScale`，外加 `globalVerticalScale` | **权重 + 全局垂直缩放** |
| **BigGlobe** | 自建 ChunkGenerator，逐列 `getFinalTopHeightD()` | 彻底掌控高度函数 |

本模组只能通过 `depth` 覆写注入高度（原版 `NoiseBasedChunkGenerator`），所以采用
"**高度场 + 山区掩码 + 全局垂直缩放 + 软上限**"的组合，对应上表的第 3 条思路。

## 6. 验证方法

### 6.1 离线（`dumpPreview`）

输出到 `temp/preview_dump/`：

- `seed_<seed>.png`：地形预览
- `biomes_<seed>.png`：Whittaker 分类图（我们的分类，不是实际群系）
- `landform_<seed>.png`：地貌图（橙=火山弧、黄=高原、红=裂谷、灰=平原、蓝=海）
- 控制台：高度分位、坡度分位、温度/湿度分位、群系分布、`familyPositive`

### 6.2 冒烟（`runServer`）

只看两件事：注册表是否报错（`Unbound values` / `Failed to parse`），
以及 `Done (x.xxx s)` 有没有异常。区块生成阶段的地物冲突（`Feature order cycle`）
**只有生成区块时才会暴露**，所以要开一次服（出生点区块会自动生成）。

### 6.3 实机探针（临时类，用完删）

标准写法：实现 `ServerLifecycleEvents.SERVER_STARTED`，在回调里做少量采样
（**≤ 9 个区块**），打完日志就删掉类、把 `TerrainRecast` 里的调用也删掉。

参考历史探针：`BiomeCheck`（地貌↔群系）、`VegCheck`（地物注入）、
`SurfaceCheck`（地表方块）、`PeakProbe`（找山）。

### 6.4 找山命令（`/terrainrecast peak`）

```mcfunction
/terrainrecast peak              # 默认半径 2000、高度 ≥ 800（相对海平面）
/terrainrecast peak 5000         # 半径 5000
/terrainrecast peak 5000 1000    # 半径 5000、只要 ≥1000 格的
```

输出最多 5 座峰：坐标、高度（相对海平面）、估算地表 Y、离你的距离。

实现是 `PeakSearch`：32 格粗扫 → 取最高的一批候选 → 步长减半爬山 → 按 256 格间隔去重。
**不生成区块**，纯采样解析高度场，半径 3000 约 15 ms。

> 坑：一开始没有去重，5 个名额全被同一座山占满（爬山都会收敛到同一个峰）。

## 8.5 数据安全提醒

开发过程中出现过一次**工作区文件被外部改动**：18 个群系 JSON 被删、5 个文件被修改，
但 HEAD 里的版本是完整的（`git status` 一眼就看出来了），用 `git checkout -- .` 全部恢复。

建议：
- 动数据文件前后都跑一次 `git status`，确认改动范围符合预期；
- 一次只让**一个脚本**写同一批文件，不要在批处理循环里"先删后写"（删完写一半就中断会留下残缺目录）；
- 恢复后务必 `build` + `runServer` 各跑一遍，注册表错误只在跑服时才暴露。
